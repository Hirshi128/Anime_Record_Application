# 好みの傾向

`/anime/insights` はログイン中の本人の記録を集計する画面です。
ホームとアニメ一覧の「好みの傾向」から開けます。

## 集計ルール

- 視聴状況が `COMPLETED`（視聴済み）の記録だけを対象にします。
- 評価の分布は SS・S・A・B・C・D の順に作品数を表示します。
- ジャンル別に視聴済み作品数、SS・Sの作品数、SS・Sの割合を表示します。
- 割合は「そのジャンルのSS・S件数 / そのジャンルの視聴済み件数」で、整数に丸めます。
- ジャンルはSS・S件数の多い順、次に視聴済み件数、最後に名称順です。
- 複数ジャンルの作品は各ジャンルに1件ずつ数えます。全体の作品数は重複させません。
- ジャンル未登録の作品も評価分布には含みます。
- ジャンル名から、視聴済み・該当ジャンル・高評価順の一覧へ移動できます。
  選択肢にない過去のタグは集計に表示しますが、一覧のジャンル絞り込みリンクは付けません。

## 限界と安全性

件数が少ないジャンルの100%は、安定した好みの推定とは限りません。
評価の分布は記録の集計であり、感想のAI解析ではありません。
視聴中・中断などは除外するため、それらの評価を含む総合的な嗜好とも異なります。

認証は既存の `requireCurrentUser` を使用します。ユーザーIDをURLで指定する機能はありません。
評価分布のSQLは本人の記録の集計値だけを取得します。おすすめは別のSQLで、
現在のフレンドがイチ押しに指定した作品のタイトル・評価・共通ジャンルと公開名だけを
取得します。感想・メール・未公開の記録は取得しません。
DBへの書き込み、追加migration、外部API呼び出しもありません。

## フレンドからのおすすめ

- 自分が視聴済みとしてSSまたはSを付けた作品のジャンルを根拠にします。
  プロフィールの好きなジャンルや感想本文からは推定しません。
- 現在フレンドとして登録されている相手のイチ押しだけを候補にします。
  申請中・解除済みの相手、自分自身、イチ押しでない記録は含めません。
- 共通ジャンル数の多い順、相手の評価が高い順、イチ押し日時が新しい順、
  記録IDの大きい順に並べ、最大6作品を表示します。確率やAIスコアではありません。
- 同じ作品名は1件にまとめます。NFKC正規化、空白の統一、英字の大文字小文字の
  統一で比較します。自分が登録済みなら視聴状況に関係なく除外します。
  別名や翻訳名を同一作品と判断する機能や、続編をシリーズ単位でまとめる機能はありません。
- 紹介したフレンドと、SS・S作品との共通ジャンルを各候補に表示します。
  他人の記録の詳細・編集画面にはリンクしません。
- 「記録する」から、自分のアニメ登録フォームへ作品名だけを引き継げます。
  フレンドの評価・感想・視聴状況・所有者はコピーしません。
  リンクを開くだけでは保存せず、本人がフォームの保存を実行して初めて記録します。
  初期入力は前後の空白を除いた200文字以内の作品名に限り、過大な値や内部の制御文字は
  引き継ぎません。これはURL初期入力の制限で、既存の手入力・保存ルールは変更しません。
- 共通ジャンルがない、フレンドがいない、該当するイチ押しがない場合は空状態です。
  少ない記録から安定した好みを断定する機能ではありません。

テストはメモリ内PostgreSQLで所有者分離、視聴状況、複数ジャンル、件数・割合を確認し、
画面テストとブラウザテストで空状態・集計表示・狭い画面・認証を検証します。
認証の本番公開条件は [公開チェックリスト](credentials-rollout.md) を参照してください。
