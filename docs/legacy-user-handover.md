# 既存ユーザーの認証引き継ぎ

管理者の信頼できるローカル端末で、本人確認済みの既存ユーザーにメールと
パスワードを追加します。公開ページから既存アカウントを取得する機能ではありません。
ID・ユーザー名・記録・評価・イチ押し・ジャンル・フレンド関係は変更しません。

## 前提

1. Node.js 24以降を使用してください。
2. 既存DBをバックアップし、分離したステージングDBで認証用migrationを適用・検証してください。
   このコマンド自体はmigrationを実行しません。
3. 管理者が既存ユーザーの本人と、そのメールアドレスの所有者を確認してください。
   IDやユーザー名を知っているだけでは本人確認になりません。既に信頼できる連絡経路や
   対面確認を使い、メールの所有確認も別途行ってください。フラグは管理者による確認の申告であり、
   自動的なメール認証ではありません。根拠が不明なユーザーの引き継ぎは行わないでください。
4. `AUTH_MODE=credentials` で検証してください。公開環境では旧ユーザー選択方式を使用しません。

## 確認のみ

PowerShellの専用端末で、接続先を明示します。最初は必ずステージングを指定してください。
`.env` は読みません。通常の `DATABASE_URL` / `DIRECT_URL` へのフォールバックもありません。
以下のURL・ID・ユーザー名・メールは例で、実際の値に置き換えます。

```powershell
$env:LEGACY_SETUP_DATABASE_URL = 'postgresql://USER:PASSWORD@STAGING_HOST/DB?sslmode=require'
npm.cmd run users:provision -- --user-id 123 --username existing_user --email owner@example.com
```

通常は読み取りだけです。IDとDBに保存されたユーザー名が完全一致すること、
認証情報が未登録であること、メールが他のアカウントに使用されていないことを確認します。
接続URLやパスワードをチャット・Git・スクリーンショットに含めないでください。
実際の接続URLをコマンド履歴に残すことも避け、必要なら端末の安全な秘密入力方法で環境変数を設定してください。

## 引き継ぎ実行

確認済みの本人が、管理者の信頼できる端末でパスワードを直接入力します。
入力は非表示です。12～128文字で、確認入力も必要です。
パスワードをコマンド引数・環境変数・ファイル・パイプで渡す方式は提供しません。
管理者が共有の仮パスワードを決めて配布する運用も避けてください。
本人が入力できない場合は、メール認証付きの招待・再設定フローが実装されるまで保留してください。

```powershell
npm.cmd run users:provision -- --user-id 123 --username existing_user --email owner@example.com --apply --owner-verified --email-verified
```

実行時にユーザー行をロックして再照合し、認証情報の追加と対象ユーザーの旧セッション削除を
一つのトランザクションで行います。既存パスワードは上書きできません。
既存記録の所有者変更、孤立した記録の取得、新しいユーザーの作成も行いません。
失敗時は詳細なDBエラーや秘密情報を表示しません。結果が不明な場合は確認のみを再実行して、
管理者がDBを安全な方法で確認してください。安易にパスワードリセットとして再実行しないでください。

実行後、本人が `/users` でメールと設定したパスワードを入力し、以前の記録・イチ押し・
フレンドが見えることを確認してください。ブラウザーの旧ID Cookieだけではログインできません。
端末を離れる前にログアウトし、専用環境変数も消してください。

```powershell
Remove-Item Env:LEGACY_SETUP_DATABASE_URL
```

## 検証と公開

`npm.cmd run verify` はメモリ内PostgreSQLで引き継ぎと通常ログイン、データ維持、
重複拒否、失敗時ロールバックを検証します。本番Neonには接続しません。
実際のNeonドライバー・ネットワーク・複数サーバー競合はステージングでの追加確認が必要です。

この実装では本番migration・既存ユーザーへの認証追加・GitHubへのpush・デプロイは行っていません。
公開前の条件は [認証公開チェックリスト](credentials-rollout.md) を確認してください。
自動メール認証・パスワード再設定・遠隔での本人招待は引き続き未実装です。
